## Product summary

- Study scriptures across religions: Christianity, Judaism, Islam, Hinduism, Yoga, Buddhism (more later).
- Base language: English. Translation languages: Spanish, French, Italian, Portuguese, German, Russian, Latin, Greek, Arabic, Hebrew.
- Show the selected text with any number of languages side by side (Column view) or one under another per verse (Stacked/Parallel view).
- For each language the user can show:
  1. **Native** — that language's own published translation (e.g., Spanish = Reina-Valera 1909), and/or
  2. **AI** — the English text translated into that language by AI, clearly labeled "AI translation".
  Both must be available **at the same time** (e.g., RVR 1909 column next to "English → Spanish (AI)" column). Default for each language = Native when one exists for that text; fall back to AI when not.
- Highlight, bookmark/save verses, write notes.
- "Ask AI" about any verse — for now via an "Ask in…" hand-off to Gemini / ChatGPT / Claude (see Study features); a built-in Ask AI panel is designed but hidden behind a feature flag for a future paid tier.
- Free product for now (decided 2026-11-03), with the source code in a **public** GitHub repo (sknapp1991/snoopwiggy). Keep the architecture production-ready in case a paid tier comes later. Licensed (copyrighted) texts must never be committed to the public repo. If one is ever added, serve it at runtime from the publisher's API or private storage.

## Tech stack

- **Next.js (App Router) + TypeScript + Tailwind CSS.** Pin dependency versions.
- **Server-side API routes for all AI calls.** The API key lives only in `.env.local` (git-ignored) and is never sent to the browser. Make the AI provider swappable behind one module (`lib/ai.ts`, selected by an `AI_PROVIDER` env var). During development the default provider for AI translations is the **Gemini API free tier** (`GEMINI_API_KEY`); keep an Anthropic adapter (`ANTHROPIC_API_KEY`) or others pluggable without touching calling code. **Local AI option (Ollama, already installed with qwen3:8b / qwen3:14b):** add an `ollama` provider used by an *offline batch script* that pre-translates chapters on the developer PC and saves them as static AI-translation files (clearly labelled with the model name). It is not used as a live server for the public site, because the PC would have to stay on and be exposed to the internet. Live translation of chapters that haven't been pre-generated falls back to Gemini. Compare quality on sample chapters before choosing.
- **Scripture text is stored locally in the project as static data**, never generated by AI. Use per-chapter JSON files (e.g., `public/texts/<work>/<version>/<book>/<chapter>.json`, served as static files) plus a catalog file describing the library tree, so pages load fast and only fetch what is displayed.
- Highlights, bookmarks and notes: stored on the device (IndexedDB via a small wrapper) for now, behind a storage interface so it can later be swapped for user accounts + cloud sync (planned: Supabase auth/DB, Stripe payments — not in this build).
- Initialize git and commit at the end of each phase.
- Deployment: **Cloudflare Workers** (via the OpenNext adapter, `npm run deploy`) on the domain **snoopwiggy.com** (DNS already on Cloudflare); auto-deploy from GitHub (`sknapp1991/snoopwiggy`). Scripture text is served as static files from `public/texts/`. No server-side disk reads (Workers has no filesystem). Next.js Cache Components stays off; it hangs on Workers as of Nov 2026. Free Workers plan limit is 20,000 static files, so watch the count as texts grow (pack per-book files or use R2 if needed).

## Copyright rules (critical — this is a commercial product)

- Use **public-domain or commercially-permitted licenses only** (public domain, CC0, CC-BY, or explicit permission). **No CC-BY-NC / non-commercial texts.** No NIV, ESV, NLT, NKJV, RVR 1960, NEG 1979, Sefaria's Steinsaltz Talmud, etc.

## Audio v2: keep playing with the screen off — *built Nov 2026, waiting on storage*

Built-in browser voices (Web Speech API) stop when a phone locks its screen, so audio v2 plays pre-made
recordings through an <audio> element, with Media Session lock-screen controls (play/pause, ‹ › verse).
- **Engine:** Kokoro-82M (Apache-2.0) on the PC's GPU (~30× real time, so a whole Bible in one voice takes about
  2.5 h and ~1.35 GB of MP3 at 40 kbps). `scripts/tts/generate.py` writes `.cache-audio/<version>/<voice>/<book>/<ch>.mp3`
  plus a timing file (each verse's start/end), which drives verse highlighting and approximate word highlighting.
- **Voices:** Kokoro has 28 English voices (20 US, 8 UK; best graded Heart, Bella, Michael, Fenrir, Puck, Emma,
  George), Spanish 3, French 1, Italian 2, Brazilian Portuguese 3. Non-English needs espeak-ng installed on the PC.
  German, Russian, Greek, Latin, Arabic and Hebrew have no Kokoro voice; they keep device voices (a Piper
  voice could fill gaps after checking each voice's dataset licence).
- **Catalogue:** `scripts/tts/catalog.ts` writes `index.json` next to the files; the app lists whatever is there.
  The player offers "Recorded" voices first and device voices second, and falls back to a device voice when a
  chapter has no recording. When a chapter ends it goes straight into the next one's recording (works with the
  screen off) and the page follows.
- **Serving:** production reads `/api/audio/...` (src/app/api/audio, Range requests for iPhone) from an R2 bucket
  bound as `AUDIO`; `.env.production` sets NEXT_PUBLIC_AUDIO_BASE=/api/audio. Local testing uses public/audio.
- **Storage:** R2 free tier is 10 GB (≈7 complete voices at 40 kbps); beyond that ~$0.015/GB-month
  (Skylar OK'd up to $3–5/month).
- **First batch (agreed Nov 2026, `scripts/tts/batch.py`, Psalms/Gospels first):** WEB Heart + Michael,
  KJV Emma + George, RVR Dora, LSG Siwis, Riveduta Sara, Bíblia Livre Dora, Greek Rapunzelina (Piper),
  Vulgate read by Sara (Italian ≈ Church Latin).
- **Voice licence checks (Nov 2026):** many Piper voices are fine-tuned from research-only or NC voices
  (lessac = Blizzard research licence; ryan = CC BY-NC-SA), so only voices *trained from scratch* on
  commercial-OK data are used. OK: el_GR-rapunzelina (CC0, from scratch). Not OK: ru_RU irina (unknown),
  ruslan (CC BY-NC-SA), denis/dmitri (fine-tuned from lessac); he_IL saspeech (non-commercial);
  de_DE kerstin (from ryan), thorsten (from lessac). Russian, Hebrew and German stay on device voices
  until a clean voice is found (e.g. a Thorsten model trained from scratch, to verify).
- **Needs from Skylar:** `npx wrangler login`, then approve creating the bucket `snoopwiggy-audio`, choose which
  voices to generate in full, and install espeak-ng for Spanish/French/Italian/Portuguese voices.

## Swipe between chapters (requested Nov 2026) — *done Nov 2026 (components/use-chapter-swipe.ts)*

Goal: go to the previous/next chapter without scrolling to the top or bottom, without accidental triggers.
- **Stacked view:** one-finger horizontal swipe changes chapter only when it is clearly horizontal
  (within ~20° of horizontal, |dy| < dx/3), long (≥ 1/3 of screen width) and deliberate (released past
  the line). Swipes that start in the left 24px edge stay reserved for opening the library drawer.
  The page follows the finger slightly with a "‹ Genesis 1" / "Genesis 3 ›" hint so the user sees
  what will happen and can cancel by sliding back.
- **Column view:** horizontal swipes keep scrolling between versions. Only at the first/last column
  does continuing to pull past the end reveal a "Next chapter ›" hint (pull-to-refresh style); the
  change happens only when dragged past the threshold. Looking across versions can never flip a chapter.
- **Also:** small floating ‹ › chapter buttons that fade while scrolling and reappear when idle.
- **Setting:** "Swipe to change chapter: one finger (default) / two fingers / off". Two-finger mode
  must not fight pinch-to-zoom: classify a two-finger gesture as a swipe only if both fingers move the
  same direction with roughly constant spacing; if the spacing changes it is a pinch.
